# Search Experience Optimization (SXO) — intent and usability

Read ../../references/AUDIT_PROTOCOL.md and ../../references/REPORT_TEMPLATE.md. SXO tests the fit of visitor intent, page type, content, usability and a useful next step. It is not a Google ranking-score formula.

## Workflow

1. Record inspected URLs, user/business goals, markets, selected viewport, actual evidence surface and limits.
2. Determine primary intent from user brief/observed page. Categorize as service, location, article, product, category, comparison, interactive tool or conversion landing page.
3. If real, current SERP results are accessible, observe the query, locale, date, positions and page-type distribution. If not, any proposed SERP/page-type mismatch is **hypothesis**, not established SERP consensus.
4. Derive 2–4 realistic visitor tasks/user stories. Mark inferred personas as assumptions without interviews/analytics.
5. Inspect first-screen orientation, information hierarchy, trust signals, pricing/conditions, accessible navigation, next action, forms and conversion friction. Run keyboard/mobile/browser tests only where actually possible.
6. Record exact evidence per URL, element or route. Separate broken interaction (confirmed) from a vague CTA or potential confusion (recommendation).
7. Prioritize functionality blockers and broad shared-template issues before cosmetic changes. Delegate actual performance to performance, WCAG to accessibility and shops to ecommerce-seo.
8. Return an intent-to-page mapping and visitor-story audit with observations, status, recommendation and verification. Optional wireframe is text-only unless an image artifact was expressly requested.

No fabricated conversion rates, keyword volumes, SERP positions, user research, conversion uplift or official UX score. Fixed word counts, one-H1 rules and required CTAs above the fold are not universal SEO pass/fail signals.
