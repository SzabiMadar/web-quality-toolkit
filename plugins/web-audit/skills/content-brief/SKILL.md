# SEO Content Brief — create or improve

Read ../../references/AUDIT_PROTOCOL.md and ../../references/REPORT_TEMPLATE.md. The deliverable is a brief for a writer, **not** published copy or a promise of improved Google rankings.

## Modes

- New page: construct audience, actual offering, reader questions, distinctive information and a suitable page structure.
- Existing page: first inspect source/URL and split findings into **keep, strengthen, add, remove** rather than proposing wholesale rewrite by default.

## Workflow

1. Confirm topic, requested market/language, page purpose, user journey, product/service facts and content-owner expertise.
2. Inspect existing page when provided; identify exact headings, descriptions, supported claims and real linking opportunities.
3. Gather actual SERP results only if accessible; preserve query, search locale, retrieval date and URLs. Without them mark rankings, volumes, difficulty and search consensus **not-tested**.
4. Map questions from initial exploration through comparison to the next step. Choose proposed page type by evidence, with hypotheses visibly marked.
5. For each proposed section specify reader question, answer scope, source/subject-matter evidence needed, original information gain, examples, media, internal link to an *existing* URL and optional contextual CTA.
6. Suggest a title/meta description appropriate to the page, not a rigid Google word/character threshold. Flag generic templated descriptions only as heuristic quality concerns.
7. Check claims using primary citations and expert sign-off on YMYL/legal/financial/medical pages. Optional scripts/check-claims.mjs flags potential uncited statements but does **not** verify truth or source quality.
8. Produce a brief with section outline, research gaps, claim QA, SEO metadata suggestions, editorial review gate and testable acceptance criteria.

Do not invent keyword volume, competitors, testimonials or customer facts. Upstream inspiration: ../../references/UPSTREAM_LEARNINGS.md .
